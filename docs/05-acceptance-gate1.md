# 一闸验收（Gate 1 · 质量运维官简版）

MVP 首版合并前，以下 **7 条**须全部满足（可演示或测试环境验证）。

**用途**：在**无真实微信支付**前提下，验证选品、下单、库存、履约与售后入口等产品链路可走通；支付模块仅允许进入「待支付」或测试环境 **mockPay**（见下文）。

**正式过线口径**：以待支付闭环 + **履约流程可走通**为准（非「已真实收款」）。

## 一闸主路径（Gate 1 冒烟骨架）

须能完整走通（可在本地 seed 预览或测试云环境）：

**首页（样板区可售全量混排）** → **（可选）顶栏筛选（区县 / 季节 / 套装·单件等）** → **商品详情** → **购物车** → **结算** → **待支付订单详情**

- **进小程序**：冷启动进入 tabBar **首页**，**不强制**先经选区页；`pages/district-select` 保留为**可选**（快捷选区、我的、结算前补选区等）。
- **首页目录**：默认展示**惠城 + 惠东**等已开放样板区可售商品**全量混排**（不含未开放区、不含套内 component 行）；卡片须**标注区县**；**非**「先点季节入口再进独立目录页」作为主路径。
- **顶栏筛选（默认「全部」）**：
  - **区县**：全部区县 / 惠城 / 惠东（与开放区配置一致）；
  - **季节**：全部 / 夏装 / 春秋装 / 冬装；
  - **类型**：全部 / 套装 / 单件；
  - （若版本提供「仅有货」等附加筛选项，默认仍为「全部」，不改变上述验收口径。）
- **购物车区属**：**不可跨区混款**；加购与当前车不同区县商品时须**提示**，用户确认后**清空购物车**再加入新区县商品（与快捷选区切换清车策略一致或等价）。
- **保留行为**：自愿选购合规横幅；结算须能确定**所属区县**（加购首件同步区属、或引导选区）。

静态核对报告（含 ✅/❌ 与代码路径）：[reports/gate1-home-main-path-static-qa.md](reports/gate1-home-main-path-static-qa.md)（对照 main 含 PR #9）。

| # | 验收项 | 通过标准（简） |
|---|--------|----------------|
| 1 | 区县隔离 | 惠城、惠东可进入选购；其他区灰显且不可下单 |
| 2 | 首页目录与 SKU | 首页默认**混排全量**且卡片标区县；顶栏可筛**区县**、季节与套/单（默认全部）；尺码 110–180；缺货不可超卖下单；**成套场景须验证套内分 SKU 扣减，任一缺码不可成套超卖** |
| 3 | 购物车与下单 | 单买/成套/批量；**跨区不可混车**（提示并清车）；生成订单且 **payStatus / status = 待支付（pending_pay）**；**成套下单覆盖分 SKU 库存扣减与缺码拦截** |
| 4 | 履约方式 | 可选快递（地址）或本区虚拟自提点；订单详情可区分 |
| 5 | 订单中心 | 列表 + 详情字段完整（商品、金额、状态、履约） |
| 6 | 售后申请 | 7 天无理由入口；状态机可流转；文案含吊牌/未穿洗条件 |
| 7 | 合规与支付占位 | 商品页含退换 + 自愿声明；无强制/指定商家表述；mock 支付仅测试环境且**标明非真收款** |

## mockPay 与支付占位说明

- **生产 / 正式环境**：用户下单后订单状态为「待支付」；界面与日志**不得**暗示已完成真实收款；无商户号时不应出现「已支付」假状态。
- **测试环境 mockPay（可选）**：仅用于联调履约、自提核销等下游能力时，可将订单推进为「已支付」；**必须在 UI、订单详情或操作日志中明确标注**「测试/mock · 非真实收款」。
- **一闸不包含**：微信支付下单、回调验签、退款（见 [06-acceptance-gate2.md](06-acceptance-gate2.md)）。

## 验收清单（可勾选细则）

下列清单与上表 7 条对应，便于测试逐项勾选；**成套分 SKU 扣库存**以第 2、3 条及本清单第 3 节为准。

### 1. 区县与款式隔离

- [ ] 仅 **惠城区**、**惠东县** 可选；其余区县在选区列表中**灰显**，文案为「即将开放」，不可进入该区商品流。
- [ ] 两区**款式 / SKU 互不串货**：订单、购物车、历史订单按区隔离或明确归属区；首页可混排浏览，**筛选区县**后列表仅该区。
- [ ] 冷启动进入 **首页** 可浏览全量，**不强制**先选区；选区页与首页「快捷选区」为**可选**入口。
- [ ] **跨区加购**：购物车已有 A 区商品时加购 B 区商品，须弹窗提示；确认后清空车再加入 B 区（取消则不加购）。

### 2. 选品与下单（待支付）

- [ ] **首页**默认展示开放区可售商品混排；顶栏 **区县**、**季节**、**套装/单件** 筛选默认 **「全部」** / **「全部区县」**，可组合缩小列表；卡片可见区县标签。
- [ ] 支持 **夏 / 春秋 / 冬** × **单买 / 成套** 组合选品（经首页筛选或直接进入详情均可）。
- [ ] 尺码可选范围覆盖 **110–180**（采用项目统一的尺码假设表，见「已知假设」）。
- [ ] 完整主路径可下单至 **「待支付」** 状态：首页（可选筛）→ 详情 → 购物车 → 结算 → 订单详情；规格、数量、金额展示正确；进入待支付**不报错**。

### 3. 库存（含成套）

- [ ] 下单或锁库存逻辑**扣减库存**；库存不足时**不可超卖**（下单失败或明确提示缺货）。
- [ ] **成套下单**：套内各 SKU **分别扣减**；任一组成 SKU 缺码时**不可成套超卖**或下单应被拦截。
- [ ] 补货后库存恢复，**可再次下单**。

### 4. 履约

- [ ] **快递配送**：可填写 / 选择收货地址，订单进入可履约状态（mockPay 后或业务定义的等价状态）。
- [ ] **自提**：每个样板区至少 **1 个虚拟自提点**；用户可选自提方式。
- [ ] 自提订单具备 **核销码**（或等价凭证）及 **自提状态**（如待自提 / 已核销）可查；待支付阶段须符合「占位码 / 支付后生效」等产品口径。

### 5. 售后

- [ ] **7 天无理由**售后入口在订单或帮助路径中**可见**（一闸可不完成真实退款，但入口与说明需存在）。
- [ ] 退换条件文案包含：**吊牌未摘、未穿洗** 等约束（与产品稿一致即可）。

### 6. 合规与隐私

- [ ] 文案与运营口径：**无**「强制购买」「指定商家」等违规表述。
- [ ] **不采集**学生身份敏感信息（如学籍号、班级强制绑定等）；一闸仅声明并使用**必要收货信息**（姓名、电话、地址等）的隐私说明。

### 7. 支付模块占位（正式口径）

- [ ] 从未支付态可正常进入 **待支付** 页 / 态，**无 JS 错误、无云函数未捕获异常**。
- [ ] **不假装已付款**：无商户号、无用户确认支付前，订单不得默认展示为「已支付」或隐藏待支付步骤（测试 mockPay 除外且须标注）。

## 测试矩阵摘要

建议按下列维度做冒烟与回归（不必穷举全部 SKU，但每格至少 1 条主路径）。**选品入口统一为首页 + 顶栏筛选**，不再以「季节页再进目录」或「必须先选区」为必测主路径：

| 浏览/筛选 | 季节（首页筛） | 购买方式（首页筛 / 详情） | 履约方式 |
|-----------|----------------|---------------------------|----------|
| 全部区县混排 / 单区筛选 | 夏 / 春秋 / 冬 | 单买 / 成套 | 快递 / 自提 |
| 惠城（筛） | 夏 / 春秋 / 冬 | 单买 / 成套 | 快递 / 自提 |
| 惠东（筛） | 夏 / 春秋 / 冬 | 单买 / 成套 | 快递 / 自提 |

**合计维度**：3 种区县维度 × 3 季 × 2 购买方式 × 2 履约方式 → 用作用例设计骨架；另加 **跨区加购清车** 至少 1 条用例。

## 已知假设（一闸）

| 假设 | 说明 |
|------|------|
| 尺码表 | 110–180 为统一通用假设表，后续可按学段 / 厂商尺码表替换 |
| 自提点 | 每区 1 个**虚拟**自提点，地址 / 电话可为配置占位 |
| 支付 | 真实微信支付、退款在 **二闸**；一闸 mockPay 仅测试环境且须醒目标识 |
| 商品数据 | 款式与价格以云开发配置或种子数据为准，与 [02-mvp-scope.md](02-mvp-scope.md) 对齐后冻结 |
| 选购入口 | 一闸主路径以 **首页全量混排 + 筛选** 为准；遗留 `catalog` 页若仍存在，不作为 Gate 1 必测主路径 |

## 非 Gate 1 范围（勿误收）

- 真微信支付、正式提审通过
- 真实物流轨迹、学校名单对接
- 学生身份采集
- 微信支付（JSAPI）、支付回调、对账与**真实退款**（见二闸）
- **惠阳区**及其他非 MVP 区县；**惠阳学段**等扩展选品维度（若产品单独立项）
- **H5 / App** 等非微信小程序端
