# 一闸验收（Gate 1 · 质量运维官简版）

MVP 首版合并前，以下 **7 条**须全部满足（可演示或测试环境验证）。

**用途**：在**无真实微信支付**前提下，验证选品、下单、库存、履约与售后入口等产品链路可走通；支付模块仅允许进入「待支付」或测试环境 **mockPay**（见下文）。

**正式过线口径**：以待支付闭环 + **履约流程可走通**为准（非「已真实收款」）。

| # | 验收项 | 通过标准（简） |
|---|--------|----------------|
| 1 | 区县隔离 | 惠城、惠东可进入选购；其他区灰显且不可下单 |
| 2 | 目录与 SKU | 区属商品展示套/单；尺码 110–180；缺货不可超卖下单；**成套场景须验证套内分 SKU 扣减，任一缺码不可成套超卖** |
| 3 | 购物车与下单 | 单买/成套/批量；生成订单且 **payStatus = pending**；**成套下单覆盖分 SKU 库存扣减与缺码拦截** |
| 4 | 履约方式 | 可选快递（地址）或本区虚拟自提点；订单详情可区分 |
| 5 | 订单中心 | 列表 + 详情字段完整（商品、金额、状态、履约） |
| 6 | 售后申请 | 7 天无理由入口；状态机可流转；文案含吊牌/未穿洗条件 |
| 7 | 合规与支付占位 | 商品页含退换 + 自愿声明；无强制/指定商家表述；mock 支付仅测试环境且**标明非真收款** |

## mockPay 与支付占位说明

- **生产 / 正式环境**：用户下单后订单状态为「待支付」；界面与日志**不得**暗示已完成真实收款；无商户号时不应出现「已支付」假状态。
- **测试环境 mockPay（可选）**：仅用于联调履约、自提核销等下游能力时，可将订单推进为「已支付」；**必须在 UI、订单详情或操作日志中明确标注**「测试/mock · 非真实收款」。
- **一闸不包含**：微信支付下单、回调验签、退款（见 [06-acceptance-gate2.md](06-acceptance-gate2.md)）。

## 验收清单（可勾选细则）

下列清单与上表 7 条对应，便于测试逐项勾选；**成套分 SKU 扣库存**以第 2、3 条及本清单第 3 节为准。

### 1. 区县与款式隔离

- [ ] 仅 **惠城区**、**惠东县** 可选；其余区县在选区列表中**灰显**，文案为「即将开放」，不可进入该区商品流。
- [ ] 两区**款式 / SKU 互不串货**：切换区县后仅展示该区配置的商品；订单、购物车、历史订单按区隔离或明确归属区。

### 2. 选品与下单（待支付）

- [ ] 支持 **夏 / 春秋 / 冬** × **单买 / 成套** 组合选品。
- [ ] 尺码可选范围覆盖 **110–180**（采用项目统一的尺码假设表，见「已知假设」）。
- [ ] 完整路径可下单至 **「待支付」** 状态：规格、数量、金额展示正确；进入待支付**不报错**。

### 3. 库存（含成套）

- [ ] 下单或锁库存逻辑**扣减库存**；库存不足时**不可超卖**（下单失败或明确提示缺货）。
- [ ] **成套下单**：套内各 SKU **分别扣减**；任一组成 SKU 缺码时**不可成套超卖**或下单应被拦截。
- [ ] 补货后库存恢复，**可再次下单**。

### 4. 履约

- [ ] **快递配送**：可填写 / 选择收货地址，订单进入可履约状态（mockPay 后或业务定义的等价状态）。
- [ ] **自提**：每个样板区至少 **1 个虚拟自提点**；用户可选自提方式。
- [ ] 自提订单具备 **核销码**（或等价凭证）及 **自提状态**（如待自提 / 已核销）可查。

### 5. 售后

- [ ] **7 天无理由**售后入口在订单或帮助路径中**可见**（一闸可不完成真实退款，但入口与说明需存在）。
- [ ] 退换条件文案包含：**吊牌未摘、未穿洗** 等约束（与产品稿一致即可）。

### 6. 合规与隐私

- [ ] 文案与运营口径：**无**「强制购买」「指定商家」等违规表述。
- [ ] **不采集**学生身份敏感信息（如学籍号、班级强制绑定等）；一闸仅声明并使用**必要收货信息**（姓名、电话、地址等）的隐私说明。

### 7. 支付模块占位（正式口径）

- [ ] 从未支付态可正常进入 **待支付** 页 / 态，**无 JS 错误、无云函数未捕获异常**。
- [ ] **不假装已付款**：无商户号、无用户确认支付前，订单不得默认展示为「已支付」或隐藏待支付步骤（测试 mockPay 除外且须标注）。

## 测试矩阵摘要

建议按下列维度做冒烟与回归（不必穷举全部 SKU，但每格至少 1 条主路径）：

| 区县 | 季节 | 购买方式 | 履约方式 |
|------|------|----------|----------|
| 惠城 | 夏 / 春秋 / 冬 | 单买 / 成套 | 快递 / 自提 |
| 惠东 | 夏 / 春秋 / 冬 | 单买 / 成套 | 快递 / 自提 |

**合计维度**：2 区 × 3 季 × 2 购买方式 × 2 履约方式 → 用作用例设计骨架；具体用例编号可在测试管理工具中扩展。

## 已知假设（一闸）

| 假设 | 说明 |
|------|------|
| 尺码表 | 110–180 为统一通用假设表，后续可按学段 / 厂商尺码表替换 |
| 自提点 | 每区 1 个**虚拟**自提点，地址 / 电话可为配置占位 |
| 支付 | 真实微信支付、退款在 **二闸**；一闸 mockPay 仅测试环境且须醒目标识 |
| 商品数据 | 款式与价格以云开发配置或种子数据为准，与 [02-mvp-scope.md](02-mvp-scope.md) 对齐后冻结 |

## 非 Gate 1 范围（勿误收）

- 真微信支付、正式提审通过
- 真实物流轨迹、学校名单对接
- 学生身份采集
- 微信支付（JSAPI）、支付回调、对账与**真实退款**（见二闸）
- **惠阳区**及其他非 MVP 区县；**惠阳学段**等扩展选品维度（若产品单独立项）
- **H5 / App** 等非微信小程序端

## 证据建议

- 测试环境 mock 支付页/日志含免责声明文案
- 运营侧一次 `adminAdjustStock` 后前端库存变化
- 成套下单用例：套内多 SKU 库存变化与缺码拦截录屏
